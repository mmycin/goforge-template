# Context

Use this command when starting work in `goforge-template`.

Read in this order:
1. `README.md`
2. `.agent/rules/architecture.md`
3. `.agent/rules/testing.md`
4. The service or package you will touch

Project facts:
- This repository is the generated application template, not the CLI product.
- Framework bootstrap lives in `boot/` (never edit).
- Framework core packages (config, database, errors, validator, console) live in `core/` (never edit).
- User-editable code lives in `internal/`: services, proto definitions, migrations, queries, tests.
- Services are wired in `internal/services/kernel.go` (auto-generated by the CLI — do not hand-edit).
- Avoid changing `goforge-cli` from this repo unless explicitly requested.

Non-negotiables:
- No package-level state in `internal/` or `core/`.
- Use constructor-based dependency injection.
- Imports must use `github.com/mmycin/GoForge/boot/...` or `github.com/mmycin/GoForge/core/...`.
- Keep HTTP, gRPC, config, and database changes consistent with existing patterns.
