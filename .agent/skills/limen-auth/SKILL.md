# Limen Authentication

Use this skill when a task involves user registration, login, sessions, password hashing, or any auth-related feature.

Full guide: `#[[file:../../../tmp/AUTH.md]]`

## What Limen provides
- bcrypt password hashing via the `credential-password` plugin
- Server-side session creation and cookie management
- Built-in HTTP endpoints: `/register`, `/login`, `/logout`, `/me`
- OAuth-ready model structure (`Account` table)
- GORM-backed storage via `limengorm` adapter

## Dependencies

```bash
go get github.com/thecodearcher/limen
go get github.com/thecodearcher/limen/adapters/gorm
go get github.com/thecodearcher/limen/plugins/credential-password
```

## File layout (inside `internal/services/auth/`)

| File | Purpose | Edit? |
|------|---------|-------|
| `model.go` | `User`, `Session`, `Verification`, `Account` structs | Yes |
| `service.go` | Limen engine init (`Initialize(db)`, `var Auth`) | Yes |
| `routes.go` | Mounts `Auth.Handler()` at `/api/auth/*action` | Yes |
| `handler.go` | Not needed — delete it | Delete |
| `grpc.go` | Not needed — delete it | Delete |
| `docs.go` | Not needed — delete it | Delete |

Proto: `internal/proto/auth/` — delete the entire directory, Limen owns its own HTTP layer.

## Bootstrap sequence

1. `goforge gen:service auth` — scaffold the directory and register in `kernel.go`
2. Delete `handler.go`, `grpc.go`, `docs.go`, `internal/proto/auth/`
3. Rewrite `model.go` with the four Limen structs (User, Session, Verification, Account)
4. Rewrite `service.go` to call `limen.New(...)` and expose `var Auth`
5. Rewrite `routes.go` to mount `gin.WrapH(Auth.Handler())` at `/api/auth/*action`
6. Update `internal/services/kernel.go`:
   - Register all four models in `Model()`
   - Call `auth.Initialize(gormDB)` before the HTTP server starts
7. Run `goforge migrate` to create the tables
8. Run `goforge app serve`

## Critical implementation details

```go
// service.go — always read APP_KEY from env, never hardcode
secret := os.Getenv("APP_KEY")

// model.go — password MUST use json:"-" to prevent hash leaks
Password *string `json:"-"`

// model.go — use soft delete on User for FK integrity
DeletedAt gorm.DeletedAt `gorm:"index" json:"deleted_at"`

// routes.go — use Any + wildcard so Limen owns the full /api/auth/* namespace
engine.Any("/api/auth/*action", gin.WrapH(Auth.Handler()))
```

## Limen HTTP endpoints (auto-provided)

| Method | Path | Action |
|--------|------|--------|
| POST | `/api/auth/register` | Create user + hash password |
| POST | `/api/auth/login` | Verify password + create session cookie |
| GET  | `/api/auth/me` | Return current user from session |
| POST | `/api/auth/logout` | Destroy session + clear cookie |

## Protecting other routes

After login, Limen sets a session cookie. To guard a route in another service:

```go
// Use Auth.SessionFromRequest in a middleware or directly in a handler
session, err := auth.Auth.SessionFromRequest(c.Request)
if err != nil {
    _ = c.Error(apperrors.ErrUnauthorized("not authenticated"))
    return
}
// session.UserID is now available
```

## Guardrails
- Never expose the `Password` field in any JSON response — `json:"-"` is mandatory.
- Always initialize Limen (`auth.Initialize`) before the HTTP server binds to its port.
- `kernel.go` is auto-regenerated by `goforge gen:service` / `rem:service` — re-add the Limen models and `Initialize` call after any CLI regeneration.
- Do not call `limen.New(...)` more than once; the package-level `var Auth` is intentionally a singleton.
- `APP_KEY` must be set in `.env` before starting the server; a missing key falls back to a dev-only string that is not safe for production.
