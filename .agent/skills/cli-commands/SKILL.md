# CLI Commands

Use this skill when you need to run, chain, or explain GoForge CLI operations.

The `goforge.sh` wrapper at the project root proxies directly to `go run app/main.go`,
so `./goforge.sh <cmd>` and `goforge app <cmd>` are equivalent inside the project.

---

## Project lifecycle

```sh
# Scaffold a new project (run outside any project directory)
goforge new

# Generate a secure APP_KEY and inject it into .env
goforge gen:key

# Remove the current APP_KEY from .env
goforge rem:key
```

---

## Service scaffolding

```sh
# Generate a full service (handler, routes, model, docs, grpc, proto)
# Creates internal/services/<name>/ and internal/proto/<name>/
# Auto-regenerates internal/services/kernel.go
goforge gen:service <name>

# Remove a service and clean up kernel.go
goforge rem:service <name>

# Generate a custom console command (lands in core/console/)
goforge gen:command <name>

# Remove a custom console command
goforge rem:command <name>
```

---

## Database

```sh
# Generate a new Atlas migration by diffing GORM models against current schema
goforge gen:migration <name>

# Apply all pending migrations
goforge migrate

# Remove the latest migration file and revert the Atlas hash
goforge rem:migration

# Dump the GORM schema as SQL (used by Atlas internally)
goforge loader
```

---

## gRPC / Proto

```sh
# Compile all .proto files in internal/proto/ and generate Go stubs
goforge gen:proto

# Compile a specific service's proto only
goforge gen:proto <service-name>

# Remove all generated .pb.go files
goforge rem:proto
```

---

## SQLC

```sh
# Generate type-safe Go code from internal/database/queries/*.sql
goforge gen:sqlc

# Remove generated SQLC code and revert database.go injection
goforge rem:sqlc
```

---

## Running the app

```sh
# Start HTTP + gRPC servers (reads .env for host/port)
goforge app serve

# Pass any console command defined in core/console/ through to the app
goforge app <command>

# Equivalent shorthand using the project shell wrapper
./goforge.sh serve
./goforge.sh migrate
./goforge.sh <any-command>
```

## Typical new-feature workflow

```sh
# 1. Scaffold + migrate in one step
bash .agent/skills/cli-commands/new-service.sh <name>

# 2. Edit internal/services/<name>/{model,service,handler,routes}.go

# 3. (Optional) Compile proto if adding gRPC
goforge gen:proto <name>

# 4. (Optional) Generate SQL bindings if adding queries
#    Edit internal/database/queries/<name>.sql first
goforge gen:sqlc

# 5. Start
goforge app serve
```

To remove a service and roll back its migration:
```sh
bash .agent/skills/cli-commands/remove-service.sh <name>
```

---

## Guardrails
- Always run `goforge migrate` after any model change — schema drift causes runtime errors.
- `internal/services/kernel.go` is fully regenerated by `gen:service` and `rem:service`; any manual additions (e.g. Limen `Initialize` calls) must be re-applied after CLI regeneration.
- `goforge gen:proto` expects proto files at `internal/proto/<name>/<name>.proto`.
- `goforge gen:sqlc` reads engine from `.env` (`DB_CONNECTION`) and rewrites placeholders (`?` vs `$N`) automatically.
- Do not run `goforge new` inside an existing project directory.
