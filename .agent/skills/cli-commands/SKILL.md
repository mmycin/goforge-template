# CLI Commands

Use this skill when you need to run, chain, or explain GoForge CLI operations.

The `goforge.sh` wrapper at the project root proxies directly to `go run app/main.go`,
so `./goforge.sh <cmd>` and `goforge app <cmd>` are equivalent inside the project.

All commands use an interactive TUI (Catppuccin theme). When a name is omitted, a form is shown. Long-running operations show a progress screen. Destructive commands (`rem:*`) show a confirmation dialog first.

---

## Project lifecycle

```sh
# Create a new project (run outside any project directory)
# Requires both project name and module path, or use the interactive wizard
goforge new [project-name] [module-path]

# Generate a secure APP_KEY and inject it into .env
goforge gen:key

# Remove the current APP_KEY from .env
goforge rem:key
```

---

## Service scaffolding

```sh
# Generate a full service (handler, routes, model, docs, grpc, proto, events)
# Creates internal/services/<name>/ and internal/proto/<name>/
# Auto-regenerates internal/services/kernel.go and kernel_models.go
goforge gen:service <name>

# Remove a service and its proto files, clean up kernel.go
goforge rem:service <name>

# Generate a custom console command (lands in core/console/)
goforge gen:command <name>

# Remove a custom console command
goforge rem:command <name>

# Add event structs and listeners to an existing service
goforge gen:event <service>
```

## Database

```sh
# Generate a new Atlas migration by diffing GORM models against current schema
goforge gen:migration <name>

# Apply all pending migrations (shows confirmation with migrator info)
goforge migrate

# Remove the latest migration file and revert the Atlas hash
goforge rem:migration

# Dump the GORM schema as SQL (used by Atlas internally)
goforge loader
```

---

## gRPC / Proto

```sh
# Compile all .proto files in internal/proto/ and generate Go stubs
# Shows a picker if no service name is given
goforge gen:proto

# Compile a specific service's proto only
goforge gen:proto <service-name>

# Remove all generated .pb.go files and gen/ directories
goforge rem:proto

# Surgically remove all gRPC infrastructure in 12 steps
goforge rem:grpc
```

---

## SQLC

```sh
# Generate type-safe Go code from internal/database/queries/*.sql
# Shows confirmation with engine info before proceeding
goforge gen:sqlc

# Remove generated SQLC code and revert database.go injection
goforge rem:sqlc
```

---

## Configuration

```sh
# Add a new config section and auto-wire it into AllConfig
goforge gen:config <name>
```

---

## Running the app

```sh
# Start HTTP + gRPC servers (reads .env for host/port)
goforge app serve

# Show version and build info
goforge version

# Show the recommended workflow guide
goforge readme
```

## Typical new-feature workflow

```sh
# 1. Scaffold + migrate in one step
bash .agent/skills/cli-commands/new-service.sh <name>

# 2. Edit internal/services/<name>/{model,service,handler,routes,events,listeners}.go

# 3. (Optional) Add events
goforge gen:event <name>

# 4. (Optional) Compile proto if adding gRPC
goforge gen:proto <name>

# 5. (Optional) Generate SQL bindings if adding queries
#    Edit internal/database/queries/<name>.sql first
goforge gen:sqlc

# 6. Start
goforge app serve
```

To remove a service and roll back its migration:
```sh
bash .agent/skills/cli-commands/remove-service.sh <name>
```

## Guardrails
- Always run `goforge migrate` after any model change — schema drift causes runtime errors.
- `internal/services/kernel.go` is fully regenerated by `gen:service` and `rem:service`; any manual additions (e.g. Limen `Initialize` calls) must be re-applied after CLI regeneration.
- `internal/services/kernel_models.go` is auto-generated — never edit it manually.
- `goforge gen:proto` expects proto files at `internal/proto/<name>/<name>.proto`.
- `goforge gen:sqlc` reads engine from `.env` (`DB_CONNECTION`) and rewrites placeholders (`?` vs `$N`) automatically.
- `goforge rem:grpc` surgically removes all gRPC infrastructure in 12 steps — it is idempotent but cannot be undone.
- Do not run `goforge new` inside an existing project directory.
- The module path is `github.com/mmycin/GoForge` — all imports must use this.
